# elastic/ — statistics gathering in the Elastic Stack

Ships the same facts the HTML report shows (DBMS_STATS operations, the
objects each one gathered, what still needs statistics, maintenance windows)
from Oracle 19c into Elasticsearch through the Filebeat and Logstash path the
rest of the Oracle telemetry uses (`elk_db_automation`), and installs three
Kibana dashboards on top. Only `SELECT`s run against the database, and
nothing on the database host talks to Elasticsearch.

```
DB host (oracle user, cron)
  elastic/export.sh            runs elastic/export_gather.sql through SQL*Plus,
     │                         validates every document against the mapping,
     │                         appends generated/orastats-gather-<source>-<day>.ndjson
     ▼
  Filebeat  (elastic/filebeat/orastats-gather.yml, a filestream input in inputs.d/)
     │  Beats protocol, mTLS, log_type: orastats_gather
     ▼
Logstash   elastic/logstash/orastats_gather.conf beside oracle.conf:
     │     prunes to @timestamp/gs/labels/host, writes with the exporter's id
     ▼
Elasticsearch  orastats-gather-{operation,task,stale,window,status}
     │         one strict index template: elastic/elasticsearch/index-template.json
     ▼
Kibana   data view orastats-gather-dataview + three Lens dashboards
         (generated by elastic/kibana/build_dashboards.py, imported by elastic/setup.sh)
```

## Documents

Five plain indices (not data streams), one per record type, all under one
`gs.*` namespace. Every document has a deterministic id, so a re-run (or an
overlapping `--days` window) overwrites instead of duplicating.

| index                       | one per                                         | `@timestamp`     | id                                 |
|-----------------------------|-------------------------------------------------|------------------|------------------------------------|
| `orastats-gather-operation` | DBMS_STATS operation (`gs.op.*`, `gs.objects.*`) | operation start | source, container, operation id    |
| `orastats-gather-task`      | object a gather operation touched (`gs.task.*`) | object start     | operation, md5(target, start)      |
| `orastats-gather-stale`     | stale or statistics-less object, per export day (`gs.obj.*`) | export time | day, md5(object)      |
| `orastats-gather-window`    | scheduler window opened (`gs.win.*`)            | window start     | container, window, start           |
| `orastats-gather-status`    | container, per export hour (`gs.status.*`)      | export time      | container, hour                    |

Every document carries `gs.source` (the exporter's `--source`, the SID by
default), `gs.db`, `gs.con`, `gs.con_id`, `gs.owner` (where there is one) and
`gs.oracle_maintained` (from `CDB_USERS.ORACLE_MAINTAINED`); Filebeat adds
`host.name` and `labels.*`. Every timestamp is a true UTC instant, so Kibana
can display any time zone.

`gs.op.outcome` condenses an operation the way the HTML report does:
`complete`, `objects_failed`, `incomplete` (objects left unprocessed),
`timed_out`, `failed`, `never_finished` (still IN PROGRESS a day later) or
`running`. `X$LOGMNR_CONTENTS` fails in every automatic run by design; it is
counted in `gs.objects.failed_expected` / `gs.task.expected: true`, never in
`gs.objects.failed`. `gs.obj.category` is `missed`, `locked`, `missing`,
`missing_subpartition`, `fresh`, `stale` or `fixed`, as in the report's
"Needs statistics" view.

## Deploy

Three places get something: the Elastic Stack host (index template, Kibana
objects, one Logstash pipeline file), and the database host (a Filebeat input,
the exporter, a cron entry). The commands below are the ones used for the lab
deployment (docker-elk 9.4.2 on the workstation, Oracle 19c CDB `cdb1` on the
`dbmint` VM); adjust host names, paths and credentials to yours.

### Prerequisites

- **Elastic Stack 9.x** with Logstash already accepting Beats on 5044 with
  mutual TLS, set up by `elk_db_automation` (its `oracle.conf` provides the
  `beats` input this integration reuses). Here: the `docker-elk` compose
  project, containers `docker-elk-{elasticsearch,logstash,kibana}-1`.
- **Filebeat 9.x on the DB host**, deployed by `elk_db_automation` under
  `/u01/app/oracle/filebeat`, with `filebeat.config.inputs` pointing at
  `inputs.d/*.yml` (hot-reloaded) and `output.logstash` pointing at the
  Logstash host (here `192.168.56.1:5044`) with its client certificate.
- **On the DB host**: the Oracle software owner (`oracle`) with `sqlplus`
  (via `oraenv`), `bash`, `python3`, `rsync` or `scp`; `/ as sysdba` access to
  the CDB (or a user that can read the `CDB_*` views and `V$CONTAINERS`).
- **On the workstation**: `curl`, `python3`, network access to Elasticsearch
  (9200) and Kibana (5601), and the `elastic` user's password.

### 1. Elasticsearch and Kibana (workstation)

```bash
cd orastats_gather_dashboard
ES_URL=http://localhost:9200 ES_USER=elastic ES_PASSWORD=changeme \
KIBANA_URL=http://localhost:5601 KIBANA_USER=elastic KIBANA_PASSWORD=changeme \
  elastic/setup.sh
```

This PUTs the index template `orastats-gather` (pattern `orastats-gather-*`),
updates the mapping of any `orastats-gather-*` index that already exists,
regenerates the Kibana objects and imports the data view and the three
dashboards with `overwrite=true`. It prints the three dashboard URLs. Safe to
re-run at any time.

### 2. Logstash pipeline (Logstash host)

Copy the pipeline file next to `oracle.conf` and restart Logstash (docker-elk
has no automatic config reload):

```bash
cp elastic/logstash/orastats_gather.conf ../docker-elk/logstash/pipeline/
docker restart docker-elk-logstash-1
```

Check that the pipeline came back with the new output (6 Oracle outputs +
awrcap + this one = 8 here) and without errors:

```bash
curl -s localhost:9600/_node/stats/pipelines \
  | python3 -c 'import json,sys; p=json.load(sys.stdin)["pipelines"]["main"]; print(len(p["plugins"]["outputs"]), "outputs")'
docker logs --since 5m docker-elk-logstash-1 2>&1 | grep -iE 'error|exception'
```

Logstash writes with the credentials it already has (`ES_USER`, here
`elastic`). With a less privileged user, grant it `create_index`, `index`
and `write` on `orastats-gather-*`.

### 3. Exporter and Filebeat input (DB host)

Copy the `elastic/` directory to the Oracle owner's home and drop the Filebeat
input into `inputs.d/` (picked up within 10 s, no restart):

```bash
rsync -az -e 'ssh -p 2200' elastic/ oracle@dbmint:~/orastats_gather_dashboard/elastic/
ssh -p 2200 oracle@dbmint '
  cp ~/orastats_gather_dashboard/elastic/filebeat/orastats-gather.yml /u01/app/oracle/filebeat/inputs.d/ &&
  chmod 600 /u01/app/oracle/filebeat/inputs.d/orastats-gather.yml'
```

Make sure Filebeat is running (it is started by `elk_db_automation`'s
`scripts/start_filebeat.sh`; the equivalent by hand):

```bash
ssh -p 2200 oracle@dbmint '
  d=/u01/app/oracle/filebeat
  pgrep -f "$d/filebeat -c" ||
    { nohup $d/filebeat -c $d/filebeat.yml >> $d/logs/nohup.out 2>&1 & echo $! > $d/filebeat.pid; }'
```

Starting a stopped Filebeat also resumes every other input in `inputs.d/`
(alert, listener, trace logs, metrics), which then catch up from where they
stopped.

### 4. First load (DB host)

Export the whole statistics history once (the optimizer keeps 31 days by
default; match `--days` to `DBMS_STATS.GET_STATS_HISTORY_RETENTION`):

```bash
ssh -p 2200 oracle@dbmint '~/orastats_gather_dashboard/elastic/export.sh --sid cdb1 --days 31'
```

Run in `CDB$ROOT`, it covers every open container. It prints a count per
record type and the file it appended to, e.g.

```
operation     9042
stale          701
status           2
task         26609
window          36
36390 documents validated
appended to /u01/app/oracle/filebeat/generated/orastats-gather-cdb1-20261022.ndjson
```

`export.sh` refuses to write anything if SQL*Plus fails or a document does not
match the index template, so a bad export never reaches Filebeat.

### 5. Verify the data arrived (workstation)

Within a minute the counts in Elasticsearch match the export:

```bash
curl -s -u elastic:changeme 'localhost:9200/_cat/indices/orastats-gather-*?v&h=index,docs.count'
```

Then open the dashboards (log in as a Kibana user):

- `http://<kibana>:5601/app/dashboards#/view/orastats-gather-overview`
- `http://<kibana>:5601/app/dashboards#/view/orastats-gather-run`
- `http://<kibana>:5601/app/dashboards#/view/orastats-gather-stale`

### 6. Schedule the daily export (DB host)

Add one line to the Oracle owner's crontab (after the night's maintenance
windows have closed):

```bash
ssh -p 2200 oracle@dbmint '
  line="30 6 * * * \$HOME/orastats_gather_dashboard/elastic/export.sh --sid cdb1 >> /u01/app/oracle/filebeat/logs/orastats-gather-export.log 2>&1"
  (crontab -l 2>/dev/null | grep -v orastats_gather_dashboard/elastic/export.sh; echo "$line") | crontab -'
```

The default `--days 2` overlaps the previous run, so a missed day is caught up
the next morning; ids make the overlap harmless. To test it under cron's bare
environment:

```bash
ssh -p 2200 oracle@dbmint 'env -i HOME=$HOME PATH=/usr/bin:/bin bash -c "\$HOME/orastats_gather_dashboard/elastic/export.sh --sid cdb1"'
```

### Exporter options

| option | default | meaning |
|--------|---------|---------|
| `--sid SID` | `$ORACLE_SID` | instance to connect to (`oraenv` is sourced) |
| `--container PDB` | none | `ALTER SESSION SET CONTAINER` first; export one PDB only |
| `--days N` | 2 | operations, tasks and windows started in the last N days |
| `--source LABEL` | the SID (`/PDB` with `--container`) | keys every document id; keep it stable per database |
| `--out DIR` | `/u01/app/oracle/filebeat/generated` | where the NDJSON goes (the directory the Filebeat input tails) |
| `--retention-days N` | 7 | delete older `orastats-gather-*.ndjson` files |
| `--stdout` | | print the validated NDJSON instead of writing a file |

The stale snapshot and the status records always describe "now", whatever
`--days` is. A 31-day run on the lab CDB takes about a minute.

### Several databases

Run the exporter on each DB host with its own `--sid` (and a `--source` that
is unique across the fleet, e.g. `--source prod1`). The documents share the
same indices; pick a database with the *Database* control (`gs.db`) or filter
on `gs.source`.

### Troubleshooting

| symptom | look at |
|---------|---------|
| `export.sh` fails | its stderr (SQL*Plus output is printed); `ORA-00942` means a missing grant on a `CDB_*` view |
| file written, nothing in Elasticsearch | Filebeat running? `/u01/app/oracle/filebeat/logs/filebeat*` (registry, connection to 5044) |
| Filebeat connected, still nothing | `docker logs docker-elk-logstash-1`: a `strict_dynamic_mapping_exception` means the template and the exporter disagree (re-run `setup.sh`) |
| dashboards empty | time picker range (default last 31 days); the "latest export" panels need an export in the last 26 h |
| cron run does nothing | `/u01/app/oracle/filebeat/logs/orastats-gather-export.log` |

### Upgrade

After pulling a new version: re-run `elastic/setup.sh` (template first, then
Kibana objects), copy `logstash/orastats_gather.conf` again if it changed and
restart Logstash, and re-sync `elastic/` to the DB host. Documents keep their
ids, so the next export simply overwrites them.

### Remove

```bash
# DB host
crontab -l | grep -v orastats_gather_dashboard/elastic/export.sh | crontab -
rm /u01/app/oracle/filebeat/inputs.d/orastats-gather.yml /u01/app/oracle/filebeat/generated/orastats-gather-*.ndjson
# Logstash host
rm ../docker-elk/logstash/pipeline/orastats_gather.conf && docker restart docker-elk-logstash-1
# Elasticsearch / Kibana
curl -u elastic:changeme -X DELETE 'localhost:9200/orastats-gather-*'
curl -u elastic:changeme -X DELETE 'localhost:9200/_index_template/orastats-gather'
for id in orastats-gather-overview orastats-gather-run orastats-gather-stale; do
  curl -u elastic:changeme -H 'kbn-xsrf: true' -X DELETE "localhost:5601/api/saved_objects/dashboard/$id"; done
curl -u elastic:changeme -H 'kbn-xsrf: true' -X DELETE localhost:5601/api/saved_objects/index-pattern/orastats-gather-dataview
```

## Dashboards

| id | title | answers |
|----|-------|---------|
| `orastats-gather-overview` | Statistics gathering - Overview | did the job run in every window, did it finish, how long, what failed, what is slowest |
| `orastats-gather-run` | Statistics gathering - Run detail | one run object by object: types, schemas, statuses, errors |
| `orastats-gather-stale` | Statistics gathering - Needs statistics | what is stale or missing now, why, and the daily trend |

Clicking a run in the overview's *Automatic runs* table opens *Run detail*
filtered to it. Open them at `http://<kibana>/app/dashboards#/view/<id>`.

The `.ndjson` files under `kibana/` are generated: edit
`kibana/build_dashboards.py` (and `kibana/lens_lib.py`, copied from
`awr_capacity_predictions/elk/kibana`), not the output. Ids are md5-derived
from stable names, so a rebuild is byte-identical unless the builder changed.

## Adding a field

The mapping is `dynamic: strict`. Add the field to
`elasticsearch/index-template.json`, re-run `setup.sh` (it re-PUTs the
template and updates the live mappings), then emit it from
`export_gather.sql`. `export.sh` refuses any document with an unmapped field
before Filebeat sees it.

## Notes

- "Latest export" panels (stale objects, container status, hours since the
  last automatic run) read documents from the last 26 hours. If the export
  stops running, they go empty while the history charts keep working.
- The Logstash file must sort after `oracle.conf` in the pipeline directory
  (it does: `orastats` > `oracle.`); its prune runs after that file's common
  filters. Events with an unknown `gs.record` are not written anywhere.
- Lens cannot draw the report's per-run object timeline (a Gantt); *Run
  detail* lists objects with their start times and durations instead.
